# Semantic Port at Scale — Protocol

Read this when the lens's scale gate fires (reachable source over ~20k lines, or census tokens over half a task context window). The primary lens (`lenses/semantic-port.md`) still defines what a good solution means; this reference defines how its Characterize/Port/Track obligations execute when no agent can hold the source. Phases are invariants with decidable exit criteria; every artifact collapses at small scale (see Scale-down), but once the gate fires none is skipped. All durable state commits atomically with the work it describes; a killed session restarted with only the repository must compute the same next action. Budget: this file stays under 3,200 words.

**Hammer fit.** Phases 0–4 instantiate the cadence's explore → decide; Phases 5–6 are implement → validate; Phase 7 is tracking-mode operation. The divergence ledger below IS the run's defect ledger, and its findings mirror into the approach registry per SKILL.md. The unit ledger lives in the product tree or the state branch — the same choice as the lens's `ledger_path` — with the `.hammer/` state file holding only the resume pointer. Seam refactors and strangler feasibility are spikes. The root boundary declaration, port map, and strategy are contract content: they pass the clarification gate before their phases exit.

## Phase 0 — Census (mechanical, no LLM)

- Before any agent reads code, run deterministic tooling: syntax census, semantic index (SCIP-class), and call/import graph with public-symbol cross-references. Static graphs miss function-valued dispatch, so union in the dynamic call edges emitted by the instrumented test run below before anything is partitioned. Regenerate on every resume instead of caching — cheaper than one agent turn.
- Declare the port's entry-point boundary, then falsify the declaration itself (reverse-dependency and external-consumer search): a wrong boundary makes every later phase consistently wrong-but-green.
- Disposition code `not-ported(dead)` only on converging evidence: statically unreachable AND never executed in the instrumented run AND cleared by a per-language dynamic-dispatch/reflection inventory (plugins, string dispatch, DI, serialization hooks). Any runtime-executed line voids the disposition. Export-level pruners (knip-class) are evidence for dead exports only, never statement reachability.
- Build the test→code map as a per-test coverage matrix — native coverage contexts where the ecosystem has them, batched per-test runs where it does not — budgeted as a Phase 0 compute job. The same instrumented run emits the dynamic call edges.
- Exit: dependency graph (static ∪ dynamic), API surface, reachability report, and test→code map committed as machine artifacts; dead code ledgered with evidence.

## Phase 1 — Partition

- Condense the unioned call graph to its SCC DAG. An SCC ports whole as one unit, or is pre-broken by a seam refactor in the SOURCE — a spike first, never split blind across languages. In tracking mode a seam refactor is either upstreamed or maintained as a rebase-able patch series recorded as ledger events; every re-pin replays the series.
- Cut at interface-minimal semantic boundaries (one feature, subsystem, or behavior), never source files. Score candidates by boundary cost — crossing symbols × contract complexity — and by serializability: a boundary whose crossing values lack a value-semantic projection (identity-based, cyclic, or lazy graphs) is a bad cut, or must carry a named projection function (e.g. Type → canonical type string) declared in the unit's equivalence relation. Interiors are unbounded (a 50k-line checker is one unit); boundaries are capped.
- Context invariant: every unit's CONSUMER-visible boundary contract fits one context alongside a consumer's own source and task brief — practically 10–20% of the smallest task window. Over-cap boundaries are re-cut; lossy summarization is forbidden. A mega-unit's interior spec is a subtree (Phase 2) its implementer reads hierarchically, so interiors never fight the cap.
- Order units leaves-first by topological strata, so every port task's dependencies are already-fixed target signatures and specs.
- Frozen upstream → target-idiom units. Live upstream (sets mode=track and activates Phase 7) → keep the port map near-isomorphic so an upstream diff routes to at most two units. Record the choice per unit as `translation_distance` in the port map.
- Quality gates, computable from the census: (1) every boundary under cap; (2) all inter-unit edges forward after condensation — best-effort mechanical: a cycle discovered at port time reopens the partition for the implicated units as an append-only event; (3) each unit's oracle test cluster touches only that unit plus lower strata; (4) tracking mode: an upstream diff maps to ≤2 units.
- Expect order 100–400 units per 1M lines. Thousands means over-fragmented; under ~50 means boundaries are over budget. Unit count is a smell test, not the load-bearing metric — the cap is.
- Exit: unit list with boundary token counts, strata, and translation distance committed; all four gates pass.

## Phase 2 — Spec tree

The spec tree is the compression datastructure that replaces the codebase as what agents read. It compresses what each task must read, never total spec bytes: do not trade clause or journey coverage for a shorter spec. Spec leaves are decoupled from port units: an ordinary unit owns one leaf; a mega-unit (whole-SCC) owns an interior node holding several capped leaves plus an index that itself fits under the cap. The unit's consumer-visible boundary contract is always one capped leaf. When the user supplies a spec package instead, audit it for clause, journey, and error-semantics coverage rather than re-deriving it; gaps become extraction work scoped to the gaps.

- Root: boundary declaration (in-scope / out-of-scope with a straddle rule), global equivalence-relation tiers, user journeys (pre-conditions plus numbered steps separating user action from enumerated observable responses — each journey later drives an end-to-end differential scenario), the must-diverge list, and the determinism-seam inventory (env flags, mock adapters) — without the seams a reimplementer cannot reproduce the oracles.
- Interior nodes: subsystem summaries that OWN shared execution machinery (run loops, schedulers), so leaves reference it once instead of re-deriving it per unit.
- Leaves: boundary sentence; numbered clauses citing file:line at BOTH definition and execution sites (behavior routinely lives outside the unit's own files); per-clause provenance tag `test-derived | doc-derived | code-only`; the unit's equivalence relation; oracle inventory with named gaps.
- Category encodes proof seam: test vectors verify at unit level, contracts at integration, domain behavior at integration or app level, journeys end-to-end. Stable IDs attach only to verifiable artifacts (test vectors, acceptance criteria, journeys); domain behavior stays hierarchical MUST-prose with every exact constant preserved — a spec that generalizes a threshold has lost behavior, and constant preservation is an audit gate.
- Behavior-first, two passes: pass 1 writes clauses from tests, docs, examples, and observed runs only, implementation embargoed; pass 2 reads source and reconciles. Code-only clauses are quarantined as possibly-incidental until a test or usage site witnesses them.
- A clause's witness must cover the exact input class it asserts: a clause extrapolated from an adjacent probe ranks code-only until a golden for that input exists — spec errors invented this way are caught by measurement, never by review.
- Coverage is accounted, not asserted: chunk the extraction input and disposition every chunk `covered | non-normative | duplicate | gap` — gaps block. Verify extraction payload integrity first; truncated inputs silently under-cover.
- Falsify before `specced` counts: a spec-blind agent probes the running source and records observed behavior FIRST, then diffs against the draft; a second agent reads only source plus draft and returns either a behavior outside the spec with a file:line or executable witness, or an attestation enumerating every boundary symbol and every clause-uncited execution site it examined — no enumeration, no pass. Omission reviewers are scored on omissions found, never on confirmations. The orchestrator seeds canaries (planted spec omissions) at a sampled rate; a falsifier that misses its canary is discarded, rerun, and the miss ledgered. Docstrings are claims to falsify, not evidence. Every finding becomes a clause or an intentional-departure entry; silence is not a disposition.
- Exit per unit: contract leaf under cap; every clause cited and provenance-tagged; chunk ledger gap-free; falsification passed including canaries; ledger advances unspecced → specced → spec-verified.

## Phase 3 — Oracle fabric

Derive oracles from the pinned source BEFORE any target code, so no oracle is shaped by the target.

- Record boundary traces: instrument the pinned source at the declared boundary while replaying its tests, examples, and generated inputs; emit language-neutral fixtures (call, args, result, error, event order) with nondeterministic seams frozen via record-replay. The trace lane is conditional on projectability: where crossing values have no tractable value-semantic projection, fall back to final-state equivalence at a coarser enclosing boundary, or to the metamorphic lane.
- Every fixture passes against the pinned source first; a failing fixture is a recording bug, never a shipped oracle.
- A self-referential fixture proves nothing: when the expected value is derived from the same computation the port performs (a digest checked against a digest the port also produced), the corpus must carry the value recorded from the source, or the clause ranks unverified — a self-consistent wrong answer passes otherwise.
- Discrimination is verified, never attested: at each unit gate, break each clause's behavior (or a committed sample) in a scratch copy of the pinned source and require its tagged fixtures to FAIL under the declared relation; the mutation command commits beside the corpus so the check replays. Verify each mutation APPLIED before counting anything — the patched site changed and the rebuilt binary behaves differently somewhere — because "mutation not applied" and "mutation undetected" are indistinguishable from outside. Coverage is clauses × {has-discriminating-test, passes} — never lines. Over-broad normalizations surface here as non-discriminating fixtures.
- Corpus framing is validated after generation: record counts, per-record delimiters, and a checksum — one malformed input (a literal newline in a generator argument) silently misaligns every golden after it.
- A vacuous pass is not a pass: a green test attributes to a unit only if it executed unit-attributable assertions (count assertions, not suite exit codes); compile-disabled or leak-check-only suites otherwise launder empty evidence into parity claims.
- Lanes that share ports, files, clocks, or processes never run concurrently with recording or baselining; a flagged interference risk blocks the run, it does not annotate it — one contended run corrupts the artifact every later disposition attributes against.
- Declare one equivalence relation per unit from the fixed menu `trace-modulo-normalizations | final-state | distributional | invariant-metamorphic`, derived by walking the language-disagreement axes (ordering, nil vs empty, unicode, integer width, concurrency). Each axis gets an explicit normalization or an explicit order-is-contract assertion, and every normalization carries a witness (source test, doc, or usage site) that the normalized dimension is not contract; the Source↔Spec falsifier attacks the normalization set. "Behaves the same" without a named relation is unfalsifiable.
- Must-diverge entries get inverse oracles: a divergence test per entry proving the target does NOT reproduce the quarantined behavior (instance identity, feeds, keys, telemetry); these run in every lane and reproducing one is a defect.
- CI lanes: frozen clause-tagged fixtures (regression); source-as-subprocess differential on freshly generated inputs (pin exact source commit, runtime, lockfile — an unpinned oracle turns parity failures into noise); metamorphic property checks where side-by-side is impractical; and a seam-perturbation lane — differential under injected latency, errors, truncation, and reordering at every seam in the determinism-seam inventory, because frozen seams exempt exactly the behavior they cover. Units with concurrency clauses add a race-detector/stress lane.
- Anti-overfitting: a held-out fixture slice lives outside worker-visible paths (state branch), with only its content hash in the product tree; porting and repair briefs carry the path exclusion, and only a non-product-writing agent evaluates it at unit gates. Regenerate the fuzz lane at every unit-gate evaluation and at least once per stratum reconciliation, recorded as ledger events. Passes-training-fails-heldout is an append-only `reopened(overfit)` event returning the unit to `ported`.
- Exit per unit: corpus committed and validated against the source; clause coverage 100% discriminating under the mutation check, or gaps ledgered UNVERIFIED (gap closure gates Phase 6); equivalence relation recorded in the unit contract.

## Phase 4 — Architecture and port map

- One global pass over spec summaries — root, interiors, and leaf boundary sentences fit one context precisely because specs compress. Decide target-native architecture, per-subsystem fidelity (translation distance), and delegation boundaries; units a target library already owns are ledgered `superseded-by(delegation)`.
- The spec tree is source-shaped scaffolding, not the target blueprint. The port map is a morphism from source units to target components — 1:1, N:1 merge, 1:N split, 1:0 dissolve into a delegated library or dead code, 0:1 target-required infrastructure. Parity is owed only at the root boundary and at seams the map explicitly marks surviving; every other interior boundary is extraction scaffolding.
- Clauses, not units, are the conserved quantity. When the map merges or dissolves a unit, its clauses re-home to the nearest surviving boundary and its discriminating fixtures are re-expressed through that interface (delegation: the library must discharge the unit's clauses, and failures are divergences). The clause ledger records every re-homing so nothing drops in translation.
- Implementation order re-derives from the TARGET dependency graph after mapping; extraction order followed source strata, port order follows target strata.
- Decide big-bang vs strangler-bridge on two axes. Whether value must ship before completion is the contract's `delivery_floor` — user intent, never an agent inference (yes → per-unit cutover behind flags with the source as production fallback; whole runtimes escalate to shadow/canary traffic). Whether CI can stay green without a bridge (agent-driven ports with a ledger and per-unit commits usually yes → big-bang with the source as CI oracle only; the production FFI bridge is then pure waste — Phase 6's frontier harness is test-only and unaffected).
- The root boundary declaration, port map, and big-bang/strangler decision change deliverable form and external effects: route them through the clarification gate before this phase exits.
- Exit: port map covers every unit including its morphism class; clause re-homings ledgered; strategy, delegation, and fidelity decisions committed and gate-approved; bridged ports carry per-unit cutover and rollback criteria.

Clean-room discipline is out of scope by default. It matters only when copying the upstream's expression would create liability not curable by license compliance (copyleft escape, proprietary source); for permissively-licensed upstreams tracked continuously it is affirmatively harmful — it destroys the diffability that keeps merges mechanical. If a port ever needs it, decide at the clarification gate and treat spec-only briefing, sanitization audits, and an output evidence bundle as contract requirements; none of that is prescribed here.

## Phase 5 — Port loop (topological strata, units within a stratum in parallel)

Units within one stratum are independent by construction — port them concurrently, not one at a time. Fan out a bounded pool of workers, each briefed per SKILL.md with only its unit's contract leaf, oracle corpus, and the already-fixed target signatures of lower strata; the controller integrates returns and owns the ledger. Serial one-unit-at-a-time porting of an independent stratum is the single largest avoidable cost of a large port. Advance to the next stratum only when the current one reconciles (Phase 6). A mega-unit's leaves parallelize the same way when independent.


1. Oracle first: the unit's corpus and equivalence relation exist and pass against the source before implementation starts.
2. Implement against dependency SPECS and already-fixed target signatures, never dependency implementations. Brief with the unit's contract leaf plus an epic-sized slice of the clause ledger — never the whole spec: oversized briefs make workers silently drop requirements. A mega-unit's implementer reads its spec subtree one capped leaf per task via the index.
3. Baseline before change: run the unit's sentinel lanes before the first code change of each iteration; pre-existing failures are recorded as gap items attributed to before the iteration, never blamed on it. Evidence tasks interleave with code tasks — never batched at the end.
4. Three-way adversarial falsification, three independent agents, no history forks: Source↔Spec (spec-blind, hunts omissions and attacks the normalization set), Spec↔Target (clause-tagged conformance), Source↔Target (differential on generated inputs). Each edge finds a defect class the other two structurally cannot. Charters are minimized repros, not review essays; edge runs carry seeded canaries — a zero-findings run that misses its canary is discarded and rerun. Findings enter the divergence ledger (the run's defect ledger): kind {spec-gap | contract-violation | divergence}, repro command, disposition, regression link; closure requires the regression entering the permanent suite.
5. Porting falsified the spec → amendment with a witness test, never a code-around; re-check sibling units sharing the amended assumption.
6. After every edit, verify it changed what it claimed: the target site differs and a behavior moved. An edit applied to formatter-reindented or already-absent text patches nothing yet reads as a fixed bug; a patch matching the wrong one of several identical sites fixes the wrong place. Confirm at the behavior, not the diff.
7. Commit the unit independently, coupled atomically with its ledger transition. No unit closes on recorded evidence: completion claims carry freshly executed evidence, and subagent success claims are verified independently before the ledger advances.

- Unit ledger states: unspecced → specced → spec-verified → ported → validated → reconciled; terminal dispositions `not-ported(evidence)` and `superseded-by(unit|delegation)`; orthogonal `blocked(on, exact-resume-command)`; back-transitions only as append-only `reopened(reason)` events (reasons include overfit and partition-cycle) — monotone in the event log, not the state value. Bridged ports append cut-over → source-retired with rollback criteria.
- Before each stratum begins, cross-check roadmap vs clause ledger vs actual code — no artifact is trusted alone; a `validated` unit must have corresponding code, tests, and passing lanes.
- Exit per unit: frozen, held-out, and perturbation lanes green under the declared relation; all three edges ran and passed their canaries; every divergence dispositioned; unit at `validated`.

## Phase 6 — Integration reconciliation

Unit parity does not compose. After each completed stratum, run frontier differential: instrument the pinned source at the boundary of the highest completed stratum (extending Phase 3 recording to internal stratum boundaries), drive the partial integrated target with root-corpus inputs projected to that boundary, and diff under the stratum's declared relations — no production bridge required. True root-boundary differential runs when the top stratum completes, and it executes every root journey as an end-to-end scenario; a port is not parity-complete until all journeys pass on the integrated target. Cross-unit divergences are ledgered against every unit they implicate; implicated units reopen. A unit reaches `reconciled` only after the stratum above it passes frontier differential.

- Exit per stratum: frontier differential green; no undispositioned divergence; zero UNVERIFIED clauses in the stratum, or per-gap user sign-off recorded as a ledger event.

## Phase 7 — Drift replay (mode=track)

Runs only when the contract's mode is track or Phase 1 found a live upstream. Recording the pinned sha in the ledger header is unconditional in every mode.

- Pin the upstream sha with submodule strength — a floating clone is not a pin. Every re-pin is an explicit ledger event and replays the seam-refactor patch series (Phase 1), so "validated against which pin" is always answerable.
- During bootstrap, accumulate upstream commits as `new` rows in the same ledger. At rebase checkpoints: a commit touching a not-yet-ported unit is dispositioned `folded-into-spec` (amend the unit's spec — never port stale behavior then patch it); commits touching ported units replay through tracking mode.
- After bootstrap, the backlog and all future commits replay through the lens's Mode 2, routed to units via the port map, with `reason` and `units` columns; unit reconciliation is derived — reconciled iff every pin-covered commit touching it is dispositioned.
- Triage dominates (~90% acknowledged in the production semport ledger): keep the acknowledge path cheap, but a behavior-bearing acknowledge requires a recorded reason the equivalence relation is unaffected; an acknowledge touching files mapped to a ported unit triggers that unit's fuzz lane; and every `implemented` disposition ports the upstream commit's own tests and reruns affected differential lanes.
- Reconcile-on-start every session: sample recent `implemented`/`validated` rows against product reality by inspection, AND sample `acknowledged` rows against their upstream diffs — the highest-volume path gets audited too. Reopen on mismatch. Upstream activity on a `not-ported` unit contradicts the census evidence: reopen it.

## Cost model

Agent-tasks are O(units): 8–12 per unit nominal (two spec passes, two falsifiers, implementation, three edges, repair, reconciliation), ×1.5–2 for retries — order 10^3–10^4 tasks at 1M lines, wall-clock weeks to months depending on stratum depth and repair rate. Budget characterization honestly: spec extraction is token-hungry by structure (parallel per-module analysis plus full from-scratch rewrites — measured at ~500KB of spec, ~125K tokens, for even a small application), it dominates early run cost, and process state (clause ledger, roadmap, iteration logs) runs roughly 2× the spec itself. A large spec is evidence of coverage, not of drift. Harness engineering is a separate line: boundary instrumentation and projection functions scale with boundary-type families, not units. No run fits a session, so the ledger and resumability are load-bearing mechanism: every transition commits atomically with its artifact, and per-task cost is dominated by boundary-contract tokens — another reason the cap, not LoC balance, is the partition metric. Archive commit rows on a rolling window; never archive unit rows — they are the resume index.

## Scale-down

At 3k lines the invariants survive with lighter artifacts: census = one reading pass (dead code still ledgered `not-ported` with evidence); partition = usually one unit; spec tree = root declaration plus one page of leaf clauses; oracle fabric = the source's tests ported plus one recorded golden corpus under a declared relation; architecture = one paragraph in the port map; port loop and reconciliation run unchanged — already cheap at one unit; drift replay = record the pin, the rest only when mode=track. What never collapses: the pinned source, the declared equivalence relation, oracle-before-implementation, spec falsification (below the gate, the lens's spec-blind probe carries it), and one ledger row per unit.
