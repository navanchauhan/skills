# Compatibility Constraint Lens

Add these requirements to the primary lens:

- Build compatibility matrices for APIs, schemas, protocols, stored data, behavior, and mixed versions.
- Identify readers, writers, callers, and external consumers.
- Distinguish additive, breaking, and behaviorally ambiguous changes.
- Test old-to-new, new-to-old, upgrade, downgrade, and partial-rollout scenarios as applicable.
- Require explicit migration or deprecation plans for intentional breakage.
