# Security Constraint Lens

Add these requirements to the primary lens:

- Define assets, actors, attacker capabilities, and trust boundaries.
- Separate authentication from authorization.
- State authorization invariants and privilege transitions.
- Protect secrets and sensitive data in transit, at rest, and in logs.
- Analyze abuse cases, auditability, and fail-open versus fail-closed behavior.
- Validate negative and adversarial paths, not only intended use.
